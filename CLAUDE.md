# wicli (`wi`)

Lightweight terminal workspace for working with AI coding tools (Claude Code, Codex) locally or on a remote box, replacing VS Code for that workflow: great terminal, tabs, quick previews and diffs of what the AI produced. No debugger, LSP or built-in editor. It should be able to build itself. Plans live in `docs/plans/` (numbered): `01-roadmap.md` is the roadmap, `02-overview-features.md` the developer-convenience feature plan (overview tab, progress, clipboard bins, send-to-agent, checkpoints), `03-dashboard.md` (parked), `04-explorer.md` (file explorer), `05-pinned-panes.md` (pinned panes); the original spec is `/Users/fahad/Downloads/Devbox terminal client implementation spec.md` (names there say "devbox"; we use wicli/`wi`).

## Rules
- Keys must stay simple and memorable: letters, arrows, Enter, Esc, Tab. No symbol keys, no chords. One global menu key opens an arrow-key menu with underlined letters.
- Nothing resident on the remote box beyond sshd. Bounded reads only. No watchers. Redraw capped at fps_cap and only when dirty.
- Every user action is an `Action` in `src/ui/mod.rs` (extensions will plug into this later).
- Local and remote share the `Workspace`/`Shell` interface in `src/workspace.rs`.

## Features in place
Local and remote shells, file explorer (`src/explorer.rs`, menu `X`: Enter shows a file in the detail pane and stays, a second Enter or `O` opens the preview pane, `E` the editor; command letters `Q J K F H G S R C P T A O E M`, any other letter or digit starts the find filter; Space marks and `M` types `@path ` mentions into the agent tab; `S` cycles name/size/modified/newest first; a dot marks files changed since open or the last `R`; state is kept per folder while wi runs), tabs with activity markers (`*` printing, `!` went quiet), previews (text, markdown, CSV/TSV, JSON, binary stub; `Ctrl-Space` then `P`), mouse (clicks and wheel; menu toggle), scrollback, bracketed paste, and clickable paths and links (Cmd+click on a Mac or Ctrl+click on Linux, also Alt+click or right-click, on a path; `file:line` opens a preview at that line, a path that is a folder (relative to the tab's folder, `~`, trailing `/`; local or remote) opens the explorer rooted there (`LinkOutcome::Explorer`), relative paths try OSC 7, the OS cwd of the pty's foreground process (`src/cwd.rs`, on click only), the workspace root, the tab's start folder, then one bounded search by trailing path (`src/pick.rs`: depth 6, 5,000 entries, 4 s, local and remote) with a picker (`Mode::Pick`) when several match, URLs and complex files go to the OS after a confirmation; `Ctrl-Space` then `O` labels everything on screen), mouse selection with copy on release, tab names (`src/rename.rs`; menu "Rename tab" (search "rename", no hotkey), a click on the active tab or a double-click on any tab opens an inline one-line prompt with the real cursor; `Tab.custom` wins over the automatic title in the strip, Info and the restart snapshot (`SnapTab.name`), never changes `is_agent()`; empty name clears it; max 40 columns, strip cuts at 24 with an ellipsis; kept across "Restart wi" only), and pinned panes (menu, Space, "pin": the active tab goes to a right or left pane beside the others; the ⇄ button swaps sides, ✕ unsplits; click a pane or menu `W` to type in it; layout remembered per workspace), preview auto-refresh (`src/refresh.rs`; a visible file preview, in any pane and whatever has the keyboard, is stat-polled every 1 s (2 s remote, one request at a time, timeouts), reloaded after `preview_refresh_debounce_ms` (default 5000) of no change or at most every 3x that, scroll/markdown/wrap/find kept, "file removed" note, switch `[defaults] preview_autorefresh`), recent files (`src/history.rs`: every previewed file recorded newest first, deduped, 30 per workspace in `state.toml` `[files]`; `H` in a preview opens the list in place, menu "Recent files" from anywhere; missing files dimmed and "file not found"; every file preview has a header row with its full path, cut in the middle), themes (Y opens a picker with colour swatches: Auto, then 16 named themes, `dark`/`light` plus VS Code style `dark-modern`, `dark-plus`, `monokai`, `solarized-dark`, `abyss`, `kimbie-dark`, `red`, `tomorrow-night-blue`, `high-contrast`, `light-modern`, `light-plus`, `solarized-light`, `quiet-light`, `high-contrast-light`, defined as `Spec` rows in `src/theme/table.rs`; arrows preview live, Enter saves to state.toml, Esc reverts; config `theme = "name"` wins, unknown names fall back to auto with a note; auto saves nothing so the next start re-detects; every theme, auto's resolved one included, paints the whole canvas - shell cells with default colours get the theme background and text, faint text is blended, OSC 10/11 queries from programs are answered with those colours - unless `[defaults] paint_background = false` leaves default colours to the terminal), "Update wi" (menu, search "update"; confirms before contacting github.com, curl/wget subprocess off the UI loop, SHA256 check, atomic replace, no sudo: prints the `sudo install` command when the folder is not writable; test hook `WICLI_UPDATE_URL`) and "Restart wi" (saves the tab layout to state.toml and execs the binary with `WICLI_RESTORE=1`; local shells start fresh in the same folders, remote tmux tabs reattach), and agent workspaces (detects `CLAUDE.md`/`.claude` and `AGENTS.md`/`.codex`, asks once, remembers the command per workspace in `~/.config/wicli/state.toml`; the start popup (`src/ask.rs`, drawn by `ui::draw_ask`) is one list of agent+command rows: remembered, `[agents.<name>] command`/`commands = [...]` from config, 8 recent commands per agent (`recent_commands` in state.toml, `last_command` still read), plain `claude`/`codex`; `O`/`E` open a bordered inline field with the real terminal cursor, Esc goes back to the list, `N` not now, `X` never here).

## Worktrees
- Parallel work happens in git worktrees under `.worktrees/<name>` (branch `unit/<name>`). Once a feature is merged or dropped, remove its worktree right away (`git worktree remove .worktrees/<name>`, check the exit status); each one carries its own ~1.5 GB `target/`. Only worktrees with active work stay.

## Build and test
- Rust is at `~/.cargo/bin` (add to PATH). `cargo build` produces `target/debug/wi`.
- Config: `~/.config/wicli/config.toml`; override with `WICLI_CONFIG`.
- Test box: `docker build -t devbox-test dev && docker run -d --name devbox-test -p 2222:22 devbox-test` (needs `colima start`). Test key: `dev/id_test`.
- Full suite: `dev/run_tests.sh` (build, clippy, unit tests, every `dev/pty_*.py`). pty tests need a venv with `pyte`; see `dev/README.md`. Bench: `dev/bench.py`.
- Self-hosting: keep a stable copy (`cargo install --path .`) for daily use and test the dev build from `target/debug/wi`, so a bug can't break the terminal you work in.
